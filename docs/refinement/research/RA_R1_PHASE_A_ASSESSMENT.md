## 0. Как читать

**Уровни доказательств** (словарь Stage 11): `КОД` — прочитано в текущем коде в этой сессии (с `файл:строка`);
`ДОК` — только документация/решение; `ВЕБ` — внешний источник с датой обращения; `НАБЛ` — наблюдение
владельца на устройстве (не воспроизводилось здесь); `ГИП` — гипотеза/вывод, требующий проверки;
`UNVERIFIED` — нужен телефон или человек. Код не является доказательством удобства (Stage 11).

**Статусы находок:** `ПОДТВЕРЖДЕНО` (код объясняет наблюдение) · `ЧАСТИЧНО` · `ПО РЕШЕНИЮ` (поведение
намеренное, по утверждённому решению; изменение = решение владельца в RA.D) · `ЕСТЬ, UX НЕ ДОКАЗАН` ·
`НЕТ В ПРОДУКТЕ` · `UNVERIFIED`.

**Что не делалось:** полный gate, тесты, сборки, запуск на устройстве (по спецификации RA.R1). Ни одна
ранее выданная PASS не переоткрывается (V3/V6); новые находки ниже — кандидаты, а не блокеры Stage 11,
кроме явно отмеченного CI (K3).

Три read-only аудита кода выполнены отдельными субагентами (онбординг/Home; планировщик/Capture;
погода/Луна/Logbook/Library/Settings); ключевые утверждения перепроверены вручную
(`tonight_home_screen.dart:51-56, 97-100`, `capture_block_dialog.dart:129-150`,
`example_capture_plan.dart:7-24`, `plan_status.dart:59-76`, `capture_assumptions_panel.dart:111-115`,
`open_meteo_forecast_parser.dart:15-27`).

## 1. Сводка (главное)

1. **Функционально продукт почти полон, визуально и по иерархии — нет.** Capture Plan, бюджет
   времени, fit, √N, хранение (условно), Logbook, Library, бэкап/экспорт, погода и Луна существуют
   (`КОД`). Удобство не доказано ни одним независимым человеческим тестом (S6.E UNVERIFIED), а владелец
   уже в третий раз (08 → обзор 2026-09-28 → review-01.10.2026) описывает одно и то же впечатление
   «сыро/плоско/перегружено». Прежний процесс в основном классифицировал такие замечания как
   «предпочтение» или «принадлежит позднему Stage». Это главный системный вывод (K16).
2. **Большинство «багов» из ревью — это утверждённые ранее решения**, а не дефекты: пример плана (RD-04),
   предложение экспозиции из прошлого light-блока (ADR-020 P2), отсутствие WB/фокуса (ADR-020 W1/F1),
   Binning/ISO-gain при классе Unknown (ADR-020 C1 + «пример рига Unknown» по выбору владельца),
   порядок Home «план первым» (ADR-019, RG-05 T1), отложенный логотип (S9.10). Их изменение требует
   явных решений в RA.D с указанием заменяемого решения.
3. **Реально подтверждённые кодом проблемы:** вспышка Tonight перед Welcome (пуш после первого кадра);
   Skip = Done; пустая шапка Home только с иконкой field mode; почти пустая и трижды повторяющая
   «нет цели» верхняя карточка планировщика; пример плана сам порождает предупреждение «No flats for: L»
   (`ГИП` из чтения кода); при смене типа блока на Flat/Bias остаётся экспозиция light (`ГИП`);
   устаревшая подпись «Change in Planning Settings»; в Library у ригов/целей нет видимой кнопки Delete
   (против правила RD-09).
4. **Научное противоречие в формулировке владельца:** «примерный уровень SNR» и концепт-график с
   абсолютным SNR = 10.1 противоречат инварианту CLAUDE.md (√N только относительный). Нужно решение и
   исследование, а не правка UI.
5. **Операционное противоречие:** PROGRESS пишет «не запушено», но `origin/main` = `b1df679`
   (PR #1 слит 2026-10-16), репозиторий публичный, и **все 3 прогона CI упали**; последний:
   «1840 tests passed, 1 failed, 2 skipped» (`ВЕБ`, GitHub API, 2026-10-17). Локальный gate S11.C2
   был зелёным на Windows.
6. **Последовательность до релиза:** редизайн затронет UI-зависимые строки Stage 11 (sweep, E2E-ключи,
   TalkBack, телефонные прогоны). Телефонные проверки S11.6 разумно проводить **после** принятых
   UI-изменений, иначе их придётся повторять (I05).

## 7. Handoff

- **Решения:** не принималось ни одного.
- **Доказательства:** код `b1df679`; GitHub API и страницы (2026-10-17): Actions runs #1–#3,
  `api.github.com/repos/Buffur/Astro-Planner`, `github.com/mmilanta/moonlit`; поиск по коллизиям имени
  (xojo.com AstroPlanner case study; apps.apple.com DarkScout; app.astrobin.com topic 216286).
- **Неизвестно:** какой тест падает на CI; поведение на устройстве (вспышка, восприятие калибровки);
  визуальное состояние экранов (рендеры не снимались); юридический статус имени.
- **Покрытие:** все 9 областей (RA-A…RA-I), каждое наблюдение ревью имеет ID и диспозицию; визуальные
  сравнения с референсами — на уровне описания (изображения просмотрены), без рендеров текущего UI.
- **Следующее разрешённое действие:** RA.R2 только по запросу владельца; реализацию не начинать.
