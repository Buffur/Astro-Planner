# S12.4 — Google Play services location in the GPL-3.0 app (S11P-03): options

> **Status:** 2026-10-17, prepared for the owner's decision (S12.4). Documentation only; nothing
> changed. **Source:** `refinement/evidence/STAGE_11_PROVIDERS_COMPLIANCE.md` (O6, S11P-03, S11P-04);
> code read 2026-10-17.

## Facts

- `pubspec.yaml` depends on `geolocator ^14.0.3`; its Android part `geolocator_android` 5.0.3 declares
  `implementation 'com.google.android.gms:play-services-location:21.2.0'` (its `android/build.gradle`,
  line 44) and calls it from `FusedLocationClient.java` and `GeolocationManager.java`. The library
  (with `-base`, `-basement`, `-tasks`) is in every release APK. It is proprietary (Android SDK
  licence terms).
- The app uses location only when the user taps "Use current position" (TASK 7.3), in the
  foreground.
- **geolocator's `forceLocationManager` setting does not remove the library**: it only chooses the
  platform `LocationManager` at run time; the Play services classes are still compiled in and
  shipped. It therefore does not change the licensing question.
- The owner holds the copyright of the app's own code and may distribute the combination. The open
  question is what others receive: GPL-3.0 §1 and §6 ask for the "Corresponding Source"; a
  proprietary library that is not a "System Library" cannot be supplied, so downstream
  redistributors (and catalogues such as F-Droid) may not treat the build as GPL-clean.
- The GitHub-only distribution does not change this (DECISIONS E.1, "Distribution: GitHub Releases
  only").

## Options

| | (a) Accept and state it | (b) Platform location only |
| --- | --- | --- |
| What | Keep geolocator. Add a GPL-3.0 §7 additional permission (a linking exception for Google Play services) to the licence notice, and state it in `COMPLIANCE.md`, the README and About | Remove Play services: replace geolocator's Android implementation with the platform `LocationManager` (an own small Kotlin channel, as the metadata channel, or a maintained plugin without Play services), keeping the current behaviour (on tap only, foreground, denied and disabled states) |
| Effect | Documents the exception; others may redistribute under it. The build stays dependent on a proprietary library | The APK has no proprietary component; GPL-clean; no Google dependency for location |
| Cost | Documentation; the About statement is a small code change (S16.8, C4) | A code Task in S16.8: a dependency change, so **high-risk** (full gate) plus a device check of L2 (denied, denied forever, services off) and a GPS fix on the phone |
| Risk | A §7 exception can only be granted by the copyright holders (the owner); fine for a single-author project | Location fixes without Play services can be slower to arrive (no fused provider); acceptable for a one-tap site position, to be measured on the phone |

**Agent's recommendation:** **(b)** for a GPL-3.0 project distributed as source and APK; **(a)** is a
valid lower-effort choice. Either way S11P-04 (TD-098, the Android notices on the licence page) still
applies in S16.8.

## What the owner's choice triggers

- (a): DECISIONS E.1 record; `COMPLIANCE.md` and the licence notice (the exception text); the About
  statement in S16.8 (C4); S17.4 checks it.
- (b): DECISIONS E.1 record; a code item in S16.8 (S12.4 (b)); `COMPLIANCE.md` updated in that change;
  S17.4 checks the APK has no `play-services-*` entries.
