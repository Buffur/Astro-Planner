## 1. The questions

- **RD-07 (08 §19, UX-14, TD-053):**
  - Should the Library's rig and target lists select for the current plan?
  - Is target selection kept there?
  - Where does Progress live?
  - Where does "Add from a photo" sit?
- **RD-14 (UX-18, 08 throughout):**
  - One name per concept: rig or equipment; Sessions or Logbook; plan or session; the dark period;
    the budget lines; "Fit tonight".
  - The words the Stage 4 decisions introduced: states, results, actions.
  - How optional session names are worded (the field itself is Stage 8's).

## 2. Evidence

### 2.1 Current behaviour (CODE VERIFIED)

**The Library** (`library_screen.dart`) has four rows: Rigs, Targets, Sites and Progress
("Integration so far, per target", `:53–60`).

**Rigs and Targets.**
- `/library/rigs` and `/library/targets` open **the same screens as the planner's pickers**,
  titled "Select Equipment" and "Select Target".
- A tap **sets the current plan's rig or target and closes the screen**
  (`equipment_selection_screen.dart:111, 161–163`; `target_selection_screen.dart:272, 355–357`).
- Editing is a pencil icon, and deleting has a confirmation.
- This is TD-053 (open since TASK 12.2), and ADR-015 §7 documents it.

**Sites.** A tap makes the site active: the planner's site, and the site of the current plan
(`sites_screen.dart:148–151`).

**Progress** (`/library/progress`, CALC-38) sums the confirmed light integration of completed
sessions per target and filter. It also appears on a session's detail. It depends on results, not
on Start: under RG-04, recorded results will feed it.

**"Add from a photo"** sits on the rig list (`equipment_selection_screen.dart:231`), so it appears
both in the Library and in the planner's rig picker (the same screen).

## 3. RD-07: options for the Library

| **TD-053** | Resolved | Resolved differently | Mitigated |
| **Change** | A manage mode for the Rigs, Targets and Sites screens; ADR-015 §7 amended | A defaults model (preferences) | Feedback only |

**Progress** (08 §19: "does it duplicate Start?"). It does not duplicate Start: it is history
summed per target, and under RG-04 recorded results feed it.

| | **PR2 — into the Logbook, as "Progress by target" (recommended)** | PR1 — stays in the Library |
| --- | --- | --- |
| **Fit with ADR-015's definitions** | The Library holds reusable things (rigs, targets, sites); the Logbook holds history and its totals | Progress is history, not a reusable thing |

## 4. RD-14: principles for names

1. **One concept, one name, everywhere:** buttons, titles, messages, empty states, the export
   labels.
2. **A plain word first;** a technical term only where it is the standard one, and then in the
   detail screen (for example "astronomical dusk" on the Night & Moon detail).
3. **Nouns that count** ("a rig", "a plan") read better in buttons than mass nouns ("equipment").
4. **Internal names stay internal:** Session, draft, window load, night key and legacy are code
   terms. Where the user needs the idea, give it a plain name.
5. **A state is an adjective on the thing** ("Saved", "Completed"), not a separate object.
6. **The unit or limit goes with a number,** never inside the name ("Dark (Sun below −18°)" becomes
   "Dark", with "Sun below −18°" shown with the times).

## 6. Recommended direction

- **RD-07:** LB1 (the Library manages; choosing happens in context; "Plan this target" is
  explicit) + PR2 (Progress moves to the Logbook) + "Add from a photo" on the rig list in both
  modes.
  - This removes the duplication 08 §19 names and resolves TD-053.
  - It keeps ADR-015's "Library = reusable things".
- **RD-14:** the glossary in §5, with **Rig**, **Plan** and **Logbook**.
  - Plan and Logbook follow the owner's own words (O1) and RG-04's flow.
  - Rig is already the word in most of the UI (43 strings, against 9 for "Equipment"), and it is
    countable.
