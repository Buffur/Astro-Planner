# S9.3 — RG-13: what each setting is for, and where it belongs

> Research for Stage 9 (`POST_ROADMAP_PLAN.md`, "Stage 9 — frozen Task sequence", S9.3), written
> 2026-09-29 against the code at `867699a`. It answers RG-13 for every visible setting before S9.4
> rebuilds Settings. The placements below are the agent's decisions under the owner's delegation
> (DECISIONS E.1, "Stage 9 decisions", D9-3); the owner may revisit any of them. Documentation only.

## 1. Question and constraints

**RG-13:** which settings match real amateur and professional needs, are they understandable, and
does each belong in Settings or in context? (08 §18; TD-050; RD-11 = S9.)

Constraints that bind the answer:
- thresholds stay user preferences, not laws (SI-006); no "recommended" value without evidence and
  no "optimal settings" section (P9.3);
- no default changes here: every default below is today's (`PlanningPreferences`);
- `Tracked` never returns to Settings (RD-08 = T3: the rig's default, the plan's override);
- no Basic/Advanced mode (RG-06): one level of disclosure at most;
- a setting that changes a calculation says so, with its unit and range.

The classes (P9.3): **A** app-wide · **B** a planning preference · **C** one plan's choice · **D** a
rig, target or site property · **E** display or accessibility · **F** information.

## 2. The settings as they are (verified at `867699a`)

`settings_screen.dart`, titled "Planning Settings", in this order: Visibility (minimum altitude,
darkness limit, dew margin, NPF k), Capture plan (feasibility margin, time between frames, five
optional overheads with fixed values), then without a heading field mode, place-name lookup, Backup
and "About & data sources". The Moon and cloud gates (ADR-013 G4, G5) exist in `PlanningPreferences`
and the calculators but have **no control anywhere** (TD-050).

## 3. One row per setting

Ranges and defaults are `PlanningPreferences`' (`lib/domain/models/planning_preferences.dart`).
"Changes" names the calculation a value feeds, or says it changes only the display.

| Minimum target altitude | B | The imaging window: time with the target below it is excluded (CALC-23, ADR-013 G2) | °, 5–60, 20 | Low altitude means more air mass, extinction and turbulence, and local obstructions differ per user; a user threshold, not a law (SI-006) | Settings · **Imaging window** |

**Not in Settings, and why:**
- **Tracking** (`Tracked`): D and C (the rig's default, the plan's override; RD-08 = T3).
- **Camera class, in-camera noise reduction, maximum exposure:** D (rig properties; ADR-020).
- **Sky darkness, elevation, time zone:** D (site properties).
- **The planner's section open states:** E, remembered automatically; no setting needed.
- **Keep screen on:** gone with the tracker (S8.4).

## 4. Decisions for S9.4 (D9-3)

1. **Title "Settings"**, not "Planning Settings": the screen holds app-wide items too.
2. **Sections, in this order,** each with a heading and one line saying what it affects:
   - **Imaging window** — "Changes when the planner counts time as usable": minimum altitude,
     darkness limit, Moon gate, cloud gate;
   - **Fit and capture time** — "Changes the capture budget and the fit verdict": feasibility margin,
     time between frames, dither, refocus, filter change, meridian flip, setup;
   - **Guidance** — "Changes advice only; never the window or the fit": NPF k, dew margin;
   - **Display** — field mode; **Privacy** — place names; **Data** — backup and restore; **About**.
3. **Each row:** the name, the current value with its unit, and a short consequence; the control
   (slider, segmented button, switch) under it; the range is the model's.
4. **The optional overheads' values become editable** (a switch plus a value field or slider within
   the model's range), because the text asks the user to measure their rig and the values are
   rig-specific. Defaults unchanged.
5. **The gates:** a switch and a percentage each, off by default; the consequence line names what is
   excluded ("Excludes time when the Moon is up and at least 50 % lit"). The opportunity and fit
   messages that say "your Moon gate" then point at a reachable control.
6. **No section is collapsed by default** (one screen, about 16 rows): disclosure would hide
   consequences; the explanation paragraph stays one line per section.
7. **Nothing moves out of Settings** into context now: every B-class preference applies to every plan
   (a per-plan override would be new product scope); field mode stays reachable from Tonight too.
