## 3. Session states and how each screen shows them

Stored statuses (ADR-014): `draft`, `planned`, `inProgress`, `completed`, `abandoned`, plus
`legacy` rows. A draft with a `plannedAtUtc` is a saved plan edited since. Separately,
`CurrentSession.hasUnsavedChanges` tracks edits since the plan was created, opened or saved
(S1.6, S1.V3).

| State | Tonight card | Planner | Sessions list | Detail |
| --- | --- | --- | --- | --- |
| Draft, never saved | "Draft" (`tonight_home_screen.dart:38–46`) | Nothing | **Not listed** (`library_viewmodels.dart:153`) | Unreachable, not listed |
| Planned | "Planned" | Nothing | "Planned" (`logbook_screen.dart:17–27`) | Open in planner, Share, Export |
| Planned, edited since | "Planned, unsaved changes" | Nothing | "Planned, unsaved changes" | Same as Planned |
| In progress | The run card on top ("In progress: …", opens the tracker, `:110–136`). The card below shows **the new draft copy** with its own Start | The planner shows the copy, not the run | "In progress" | "Open tracker" |
| Completed | — (not current) | — (opening copies it) | "Completed", planned vs actual, "Edit results" | "Edit results", "Plan again (copy)" |
| Abandoned | — | — | "Abandoned" | "Plan again (copy)" |
| Legacy | — | — | "Legacy log", a chip | Stored text only |
| No current session | "Current plan" | — | — | — |

The filters group Draft and Planned together as "Planned" (`library_viewmodels.dart:66–76`), but
pure drafts never reach the list.

### 6.1 The owner's answers (2026-09-27, after S4.R1 was accepted)

Recorded as clarifications of 08, not as decisions.

- **O1:** the concern is not which screen appeared. It is product feedback: the owner sees no
  practical reason for a separate Start → Tracker → Results workflow. The intended flow is
  *Planner → create and save the plan → image → Logbook → record how it went*. The user should not
  operate the app during imaging (+1, −1, Reject, Pause). This is input to S4.R2, **not** an
  instruction to delete. S4.R2 is to analyse what the current flow provides, whether each part is
  removed, simplified or moved to the Planner or the Logbook, and present the trade-offs.
- **O2:** yes, the Tonight hierarchy. The point is that the screen does not reflect how important
  planning is; it is not a request to move the site card down. The ordering is S4.R4's decision.
- **O3:** yes, Tonight's session card ("Draft", then "Open planner"). Draft may stay an internal
  lifecycle state while its separate user-facing presentation is removed, merged or renamed. This
  is S4.R3's decision.
- **O4:** the report proposed only **Completed / Not completed**. Per-filter integration, kept or
  rejected counts, and other detailed actuals are **not** established requirements; S4.R2 may
  evaluate them as options against the planned-vs-actual intent. The key question: how much
  post-session information preserves the planned-vs-actual value without a live tracker?

## 7. The S4.E script (owner-run quick tests)

Optional and non-blocking (DECISIONS E.1, "Stage 3 closed; Stage 4 planning decisions"). Run
whichever you can, whenever you like, preferably before S4.R4. Write the answers into §7.4, or send
them in chat. Nothing is measured by the app; no personal data about participants is recorded.

**Device rules** *(corrected 2026-09-28, S6.E step 1, for S4V-02: the original said Tests A and C
"only look at the app", but Test A's step 1 changes the current plan and Test C starts a run, and
both are stored)*:
- **No test only looks.** Every planner edit is saved at once (the plan autosaves), Save plan
  stores a plan in the Logbook, and Track live starts a run that stays in the Logbook when abandoned.
- **The safest place is the separate `.s2check` debug package** (its own app and data beside yours;
  the agent installs it only when you ask). Never reset, clear or uninstall your own app
  (`io.github.chacha12.astroplanner`): it holds real data.
- **Test A on your own app** is fine if you do this first: in the planner, **Save plan** your current
  plan (so nothing is lost), then use **⋮ → New plan** for the test plan. Afterwards you can open
  your saved plan again from the Logbook. A never-saved test plan is removed when you replace it
  and choose Discard.
- **Test B** needs a fresh install: `.s2check` or another phone. Never your own app's data.
- **Test C** starts and abandons a run, which the Logbook keeps: run it on `.s2check` only. If you
  must use your own app, make sure no run is in progress first (Tonight shows a run card if one is),
  use a test plan made as for Test A, and expect an entry for the abandoned run in the Logbook
  afterwards.

### 7.1 Test A — five seconds (you, or anyone)
1. Set up a normal plan for tonight: a site, a target, a rig (on your own app, first as the device
   rules above say: Save plan, then ⋮ → New plan). Add blocks, or tap "Start from the example plan"
   (S6.8: a new plan starts empty).
2. Show Tonight to the person for five seconds, then hide it. Ask:
   - "Can this plan be imaged tonight?"
   - "What would you tap to change the plan?"
   - "Is the plan saved?"
3. Open the planner and show its first screen for five seconds, then hide it. Ask:
   - "Which target, which night, and is it saved?"
   - "Does the plan fit the night?"
4. Record the answers word for word, and whether each was right.

### 7.2 Test B — first run (someone who has not used the app)
1. On a fresh install, hand over the phone: "Set up your site and a rig, and make a plan for
   tonight." Do not help.
2. Note:
   - where they hesitate for more than about 5 seconds;
   - whether they notice that M42 and the example rig were chosen for them *(since S6.8 nothing
     is preselected: note instead whether they find how to choose a target and a rig, and whether
     they understand the "Example rig" label)*;
   - whether they find Save and Start, and what they think each does *(since S6.2: Save plan in
     the bottom bar, and Track live (optional) in the planner's ⋮ menu)*;
   - the time to a plan they are happy with.

### 7.3 Test C — darkness (you, outside at night)
1. After 15 minutes in the dark, turn red mode on from Tonight.
